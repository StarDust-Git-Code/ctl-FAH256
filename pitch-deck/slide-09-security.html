Security Architecture

Defense in depth — five layers of cryptographic & physical protection

Five-Layer Defense Model

Layer 1: Transport & Authentication

TLS 1.3 + HMAC-SHA256 per packet. Device-unique key stored in ATECC608B secure element. Prevents MITM, injection, and spoofing.

Transport

Layer 2: Hash Chain Integrity

SHA-256(prev_hash || current_payload). Genesis block at shipment creation. Any insertion, deletion, or reordering breaks the chain immediately. Append-only by design.

Integrity

Layer 3: Replay Protection (EID)

UUIDv7 (time-ordered) Event IDs. Server maintains Redis set with 24h TTL. Duplicate EIDs rejected in O(1). Prevents capture-and-replay attacks even if HMAC key compromised.

Anti-Replay

Layer 4: Physical Tamper Detection

MPU6050 6-axis IMU detects tilt >30°, shock >3g, box opening. Tamper flag embedded in every packet. Secure element key zeroized on severe tamper (future).

Physical

Layer 5: Chain of Custody

QR-based dual-driver handoff. GPS + timestamp + dual signatures. Handoff events linked into shipment hash chain. Non-repudiable accountability at every transfer point.

Accountability

Key Management

🔑

Per-Device Unique Key

Generated in secure element at provisioning. Never leaves chip. Used for HMAC signing.

🔐

Server Key Derivation

HKDF(device_id, master_secret) → verification key. Master secret in HSM/KMS. Compromise of one device ≠ others.

🔄

Key Rotation (Future)

Periodic re-keying via secure OTA. Old keys archived for historical verification. Forward secrecy for new packets.
